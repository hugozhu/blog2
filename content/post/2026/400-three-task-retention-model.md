上一篇 [两个对手，同一套打法](https://hugozhu.site/post/2026/399-two-rivals-one-playbook/) 里，我写 Grok Bot 和 Claude Cowork 两个团队怎么做产品，里面藏了一个我没展开的细节：主持人 Lenny Rachitsky 说，他已经把自己的不少用例从 Cowork 和 Codex 迁到了 Grok Bot 上——迁得非常快。

文章发出去之后，这句话一直在我脑子里转。媒体叙事是「桌面 Agent 是新大陆，用户圈地之后就不会再动」；可生态里最重度的用户、播客主持人本人，一个周末就把家搬了。

那么问题来了：**用户从 Cowork 迁到 Grok Bot，代价到底大不大？**

我的答案分两半：任务搬家便宜，关系搬家贵。一个用户能迁走多少，取决于他在这个产品里存放了什么。这篇文章用我自己做样本来拆——我给自己的数字员工「涌现」搬一次家，看看什么带得走，什么带不走；拆完你会发现，「带不走的东西」正好回答了第二个问题：AI 产品满足用户的哪三个任务，才能把他变成长期付费用户。

## 一、便宜的那一半：配置天然可携带

先看带得走的。

技能、连接器、配置文件、对话记录，全都能导出。SKILL.md 本质是 markdown 加脚本，MCP 正在成为事实标准，同一份配置理论上哪家都能用。这部分资产搬家，成本以天计。

但这里藏着一笔容易被忽略的账：**配置可携带，调优不可携带**。

同一份技能，换一个模型跑，表现会变——哪一步容易跑偏、哪里需要停下来找人确认、兜底话术怎么写，全是针对当前模型一点点调出来的。我的博客流水线里有几十条这样的规则，比如「评估打分低于 18 分就停下来重写，不许说『勉强可以』」，每一条都是踩坑之后打的补丁。换模型等于换解释器：源代码拷得走，测试要全部重跑一遍。

有人会说，对话记录也能全量导出，灌给新产品不就把记忆迁过去了吗？文字可以导入，权重导入不了。几百次交互里，哪条偏好是用户纠正过三次、碰不得的红线，哪条只是随口的玩笑——这个权重是交互喂出来的，不是文件读出来的。

所以第一部分的判断是：**配置迁移越便宜，切换成本就越往配置覆盖不到的地方集中。** 别把护城河押在配置格式上，那是最先被标准化冲垮的一层。

## 二、贵的那一半：三样搬不走的资产

真正贵的东西，用「涌现」做样本一目了然。假设我今天把它整个迁到 Grok Bot 上，有三样东西留在原地：

**第一样：积累的记忆。** 它知道我的排版规范、标题口味、哪些内容对外发布前要脱敏、哪种插图风格会被我打回。这些不在任何配置文件里，长在几百次交互的权重里。归零重来，意味着我用几个月调教出来的默契，要再花几个月调教一遍。

**第二样：调教好的周期任务。** 每天早上八点，涌现跑一轮「早读」：读公众号后台、读 GA、digest 小红书、更新 token 消耗、读 aibase——五步，预算一小时（这个任务出过一次故障，我写过一篇 [谁停掉了数字员工的早读](https://hugozhu.site/post/2026/390-who-stopped-the-morning-reading/)）。表面看，这就是一条 cron 加一段 prompt，导出只要一分钟。但底下全是隐性规则：某个数据源超时了怎么办、抓回来的内容异常了是跳过还是报警、消息发重了怎么兜底——最后这条我用真金白银的教训换过：消息接口不幂等，会话中断后重发，同一条消息会发出去好几遍。一个跑顺了三周的周期任务，不是一个配置，是一个培训了三周的在岗员工。

**第三样：已授予的自主权。** 涌现可以直接发钉钉消息、可以直接往博客仓库 push、可以在一批低风险操作上「别问我，直接做」。这些授权是几个月里一条一条给的，每给一条都以信任为前提。换产品等于新员工入职：所有权限重新申请，所有信任重新证明，而信任重建是最慢的那件事。

这三样合起来，就是「关系」。换一个员工，简历（技能配置）可以带走，但他脑子里的业务上下文、他名下的例行事务、你对他的信任，都留在这家公司。

Cowork 到 Grok Bot 的迁移还多一层特殊性：一个是本地桌面 Agent，文件在你自己的机器上；一个是云端电脑，Bot 带着自己的虚拟机住在云上，好处是合上笔记本它还在跑。这个方向的搬家不是平移，是数据托管关系的变更——对敏感数据的用户，这是一道额外的门槛；对「关机也要跑」有刚需的用户，这是额外的诱惑。两边都在为「数据放在谁那里」重新签一次心理合同。

判断句放在这里：**切换成本不来自产品功能，来自用户存放在产品里的资产。**

功能锁不住人。模型质量六个月被追平，价格战更快——我在 [中国 SaaS 厂商的护城河应该怎么建](https://hugozhu.site/post/2026/206-china-saas-moat-war-sequoia-keynote/) 里写过，纯技术优势在中国市场的半衰期是六到十二个月。企业侧同样成立：[AI 钉钉的护城河](https://hugozhu.site/post/2026/297-dingtalk-moat-org-graph-collaboration-flywheel/) 不在 AI，在组织图谱——企业把审批链、汇报线、协同历史存在了平台上。本文说的只是同一条规律的个人版：个人用户把记忆、例行事务和授权，存在了桌面 Agent 里。

顺带收回开头那个悬念。Lenny 为什么迁得快？我猜，恰恰因为他迁的是用例，不是托付——用例是任务，任务是便宜的（这一点我没有验证他的完整配置，属于推测）。真正的问题不是「他迁走了什么」，而是「他在 Cowork 里留下了什么」。留下的越少，走得越快；这反过来就是产品该做的事：**让用户往你这里存东西。**

## 三、三个任务：另外两个是高频日常和低频深度

于是第二个问题有了形状。一个 AI 产品，如果能满足用户三个任务的需求，就能把他转化成长期付费用户——其中一个最好是周期性跑的任务。另外两个是什么？

我的答案：**一个高频日常任务，一个低频深度任务。** 三个任务对应三种经济功能，各占一个锚：

| | 周期任务 | 高频日常任务 | 低频深度任务 |
| --- | --- | --- | --- |
| 角色 | 留存锚 | 习惯锚 | 价值锚 |
| 典型形态 | 晨报 digest、监控、周报 | 邮件分诊、纪要转待办、随手起草 | 深度研究、数据分析、搭一个自动化 |
| 经济功能 | 退订变得有代价 | DAU，每天打开的理由 | wow moment，ROI 在这里算出来 |
| 对用户 | 不在场时仍在干活 | 单日痛点够痛、单次出错代价低 | 手工做不了或舍不得花时间 |
| 我的对应物 | 早读 | 消息分诊、存笔记、草稿润色 | 博客流水线、专项调研 |

**周期任务是留存锚。** 它的特殊性在于：它在用户不在场的时候持续运行。取消订阅不再是「少用一个工具」，而是「裁掉一个还在干活的员工」——这个心理动作重得多。而且它持续产生上下文：每跑一次，就往产品里多存一点资产。

**高频日常任务是习惯锚。** 它不负责惊艳，负责每天被打开。它还有一个隐藏功能：高频交互是记忆的主要来源——越用越懂你，直接反哺第二节说的切换成本。习惯锚和价值锚在这一点上是咬合的。

**低频深度任务是价值锚。** 用户付费的决策时刻几乎都发生在这里：一次手工要花两天、Agent 半小时交付的深度研究，一份能直接拿去汇报的产出。wow moment 产生口碑，ROI 在这里被算出来，转化在这里完成。

三个任务不是并列的清单，是一个有先后、有因果的飞轮：

```text
   低频深度任务          高频日常任务           周期任务
  （价值锚）            （习惯锚）            （留存锚）
      │                    │                    │
  「哇，这也能做」  →   「每天都在用」   →   「不敢停了」
   试用转化              记忆积累             资产沉淀
      │                    │                    │
      └────────────────────┴────────────────────┘
                           │
                    用户存放的资产
                           │
                     切换成本 = f(资产)
```

用户因为深度任务进来（试用），因为高频任务留下（习惯），信任建立之后，才肯交出周期任务（托付）。注意这个时序的产品含义：**周期任务是转化的结果，更是留存的锁**——所以别等它自然发生，应该在第一周就引导用户建起第一个 trigger，哪怕是很小的一个。

入选标准比分类更重要，选错任务，三个也留不住人：周期任务要有外部 deadline、失败可兜底、输出结构化（每天八点的早读，三条全占）；高频任务要单日痛点够痛、单次出错代价低（消息分诊错一条能人工补救，所以敢交给它）；深度任务要产出可分享的 artifact（博客、报告、能演示的东西）。

反过来看失败组合也成立：三个都是一次性任务，等于随时免费迁移，留存为零；只有高频没有周期，习惯可以被打断，用户走时没有沉没成本；只有周期没有深度，用户从没见过 wow moment，信任建立不起来，周期任务根本不会被交出去。

## 四、长期付费，是给自己存放的资产付利息

现在把两个问题合上：三任务结构，就是切换成本结构。

深度任务沉淀调教，高频任务沉淀记忆，周期任务沉淀托付。三个任务都在你这里，用户的资产就全押在你这里——迁移自然贵，续费自然便宜。所谓长期付费用户，本质是持续为自己存放在产品里的资产付利息：订阅费是利息，资产是本金。产品竞争到最后，争的不是谁的模型强，是谁手里押着用户的本金。

对做产品的人，这个模型给出两个动作：一，别在配置格式上建壁垒（最先被标准化冲垮），把力气花在记忆层和 trigger 的所有权上——那是本金所在；二，新用户的第一周，目标不是让他惊艳，是让他存下第一笔资产：跑通一个高频任务，建起第一个周期 trigger。

对用产品的用户，它是另一面镜子：审视一下自己的三个任务分别放在哪里。哪个产品握着你的周期任务、你的记忆、你的授权，你就已经用资产给它投了票——嘴上说「哪个模型强我用哪个」，手上的资产会诚实地告诉你，你其实走不了。

我更好奇的是反方向的问题：当模型换代让旧的调教全部失效——换解释器、测试全部重跑——用户的资产是会被迫清零、重新存放一次，还是能跟着开放标准一起迁移？如果每次模型换代都是一次强制搬家，那今天的留存锚会不会只是暂时的？你在自己的 Agent 上观察到了什么，欢迎留言讨论。
