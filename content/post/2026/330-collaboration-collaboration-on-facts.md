上周我刚发布《[数字员工是下一个十年的故事](/post/2026/329-digital-employee-next-decade/)》。今天读到一篇 36 氪 首发：清华背景的团队奇点逃逸完成千万级种子轮融资，做 AI 原生团队协作操作系统 Nexus。

读完之后我的第一反应不是「又一个竞品」，而是：

> **这个命题，正在从一个人的判断，变成一个被资本定价的方向。**

这不是巧合。当一个论点独立地从不同起点被推导出来——我做企业协作基础设施，他们做多智能体研究——它大概率触到了某个真实的结构。

## 命题收敛：AI 进企业，缺的都是身份

Nexus 创始人薛传奕的原话：

> 「今天，Agent 已经像能力出众的个体，但它们还没有真正进入组织。」

以及他对「AI 进入组织」的定义：

> 「不是企业采购了多少 AI 账号，也不是员工调用了多少次模型，而是 AI 的工作能否进入组织的任务、知识和责任体系。」

这和《数字员工是下一个十年的故事》里的核心命题是同构的：

> Agent 能解决能力问题，而数字员工解决组织问题。能力决定它会不会干活，身份决定它能不能上岗。

两个团队，不同的起点，收敛到同一个判断：**AI 进企业的瓶颈从来不是模型能力，而是组织接口**。我在《[Claude Tag 的 Agent Identity](/post/2026/272-claude-tag-agent-identity-enterprise-ai/)》里把这个断层叫做「借用人的身份做事」；他们把它叫做「协作断层」。名字不同，病灶相同。

## 协作断层的一个具象场景

36 氪 报道里有个场景，比我写过的任何案例都具象：

> 产品经理把需求交给一个 Agent 梳理，研发同时让另一个 Agent 修改代码，运营则在第三个对话窗口里研究发布方案。几个小时后，每个 Agent 都完成了自己的部分。但当三项工作需要合并时，团队才发现，没人清楚另一个 Agent 做过什么、为什么这样做。
>
> 于是，人重新回到信息中转站的位置：复制对话、补充背景、核对版本、拼接结果，再把同一件事向不同 Agent 解释一遍。

这是今天的日常。它揭示了一个被忽视的问题：

**过去的协作断层，是人和人之间的；现在的协作断层，是 Agent 和 Agent 之间的。**

《数字员工是下一个十年的故事》讲的是组织如何给 AI 发身份——那是组织对 AI 的真相供给。但还有另一半：**AI 与 AI 之间，也需要共享同一份事实**。三个互不相识的 Agent，本质上就是三个各自维护一份私有现实的员工——组织里出现三套互相矛盾的「事实」，比没有事实更糟。

薛传奕的说法很精准：

> 协作首先是对事实的协作。如果每个 Agent 理解的目标、任务状态和验收标准都不一样，能力越强，可能只是更快地朝不同方向执行。

这句话值得所有做多 Agent 编排的人贴在墙上。**先对齐事实，再分工执行**——顺序反了，能力越强，分裂越快。

落到技术上，「共享同一份事实」意味着什么？Nexus 的做法是把工作对象化：一项工作不再只是一段自然语言指令，而是一组结构化字段——**目标、负责人、依赖关系、权限、当前状态、执行证据、验收结果**。人、Agent、任务、知识、工具都是相互关联的对象，新加入的 Agent 可以沿图找到前序决策和上下游依赖。

这和《[两个数字员工，一个组织](/post/2026/302-two-digital-employees-one-org-best-practice/)》里的实践是同构的：我的两个数字员工之所以能持续运转，不是因为它们足够聪明，而是因为 **每一次改动都有 commit 记录、每一次上线都有审计痕迹、每一个任务都有明确的责任人**。对象化的组织状态，就是 Agent 的长期记忆外置——会话会结束，但工作对象不会消失。

## 自进化的三个环节：补上了我缺失的一环

Nexus 的另一个主线是自进化。这里有一段我认为比整篇报道都重要的设计：

> 系统可以根据反馈提出候选改进，例如调整上下文组织方式、模型路由、任务拆解或工作流配置。但这些变化不会直接进入真实生产环境，而要先通过独立评测，比较效果、稳定性、成本和风险，再由治理机制决定采用、限制、拒绝或回滚。

把它拆成三个环节：

```
真实反馈驱动 → 独立评测 → 治理采用
```

这条链为什么重要？因为它补上了《[企业最有价值的 AI 训练数据，不是文档内容，是隐性知识](/post/2026/325-intelligence-exhaust-data-value/)》和《[私有 Eval 是终极护城河](/post/2026/327-private-evals-ultimate-moat/)》里我没有展开的一环。

那两篇讲的是：**学习信号要捕获**（协作中的纠错和验收才是高价值数据），**学习信号要归企业所有**（eval、技能、记忆是护城河）。但「信号」到「能力」之间还有一步没讲透——

> 信号如何变成 **经过验证的、不会让系统退化的** 能力改进？

答案就是这三个环节。而且他们点破了一个反直觉的前提：

> 自进化的前提不是赋予 Agent 无限自主权，恰恰是建立更严格的证据和治理边界。

这和《[Agent 时代的权限：从 RBAC 到五层信任架构](/post/2026/314-agent-era-permission-five-layer-trust/)》的结论严丝合缝：**自主性和管控不是对立面，自主性必须以管控为前提**。一个能自由改写自己的系统不叫自进化，叫失控；一个每次改进都要回答「为什么改、改了什么、是否真的更好、能否撤回」的系统，才配叫自进化。

## 真正的竞争结构：双向奔赴

现在说竞争。表面上看，Nexus（AI 原生团队协作操作系统）和钉钉（组织协同平台 + dws 数字员工基础设施）定位重叠。但拆开看，这是一场 **双向奔赴** 的竞争：

| | 创业公司（Nexus） | 存量平台（钉钉） |
|---|---|---|
| **已有** | 自进化架构、图原生设计 | 组织图、身份体系、权限审批、存量协作数据 |
| **要建** | 组织状态本身（从零） | 自进化闭环（改造） |
| **劣势** | 没有真实组织的规模和数据 | 历史架构包袱 |

组织基础设施是一个 **双面资产**：

一面是 **组织状态**——身份、权限、任务、知识、责任链。这是存量平台几十年积累的护城河，创业公司要从零重建。

另一面是 **自进化闭环**——反馈捕获、独立评测、治理采用。这是新架构问题，存量平台要改造，创业公司轻装上阵。

关键在于这两面 **互相需要**：

- 没有组织状态，自进化没有环境——反馈从哪来？改进往哪落地？
- 没有自进化，组织状态只是静态流程工具——Agent 做了很多工作，却没有从工作中学会什么

所以这场竞争的胜负手不是谁先喊出口号，而是 **谁先合拢飞轮**：

```
组织协作 → 真实反馈 → 独立评测 → 治理采用 → 更强的 Agent → 更深的协作
```

薛传奕自己说得清楚：

> 「协作和自进化不是两条平行路线，也不是先后发生的两个阶段。两者相互依赖，也相互强化。」

## 窗口正在打开

回到开头。我说「命题正在被资本定价」，不只是修辞：

- 星连资本、水木创投领投，奇绩创坛跟投——头部早期资本开始为「AI 时代的组织基础设施」这个命题出钱
- 一个强化学习 + 多智能体背景的研究团队，没有选择做垂直 Agent（更快变现的路），而是选择做最底层的组织方式——他们赌的是范式，不是功能
- 「单个 Agent 功能很容易随着模型升级被追平，更值得看重的是组织在持续使用中积累的状态、对象关系、评测基线和协作策略」——这句资产论，和《私有 Eval 是终极护城河》的商业结论完全一致

范式之争的特点是：**入场早的人定义规则**。当组织图开始为数字员工留出格子，当协作系统开始记录 Agent 的执行证据，当自进化的每一次改进都要过治理审批——这些接口一旦被某种形态占据，后来者只能兼容，很难重来。

上一个十年，企业买的是「更聪明的 AI」；下一个十年，企业买的是「能进组织、能积累、能被审计的 AI」。

数字员工十年论不是预测，是倒计时。窗口正在打开——无论是谁，先到者定义这个品类。
