昨天我做了一件拖了半年的事：把自己博客的搜索系统整个换掉了。

不是自己动手——我给一个 AI Bot 发了一句话：「我 Blog 上的搜索基于一个几乎没人维护的组件，内容越来越多之后变慢了，给我一个更优的方案。」三个多小时后，它交回来一个 676 行的 PR，我花了不到二十分钟验收，点了 Merge。

值得琢磨的是前面那半年。「重写搜索系统」这件事在我脑子里挂了很久，一直被我归为「重要的事」，但每次要动手，我都会先估算成本：看懂旧的 WASM 组件要一天，设计新方案要一天，改完测试再上线又要一天——三天工时，还有把线上搜索搞坏的风险。于是它一直是「下个月再说」。

同一件事，换个成本结构，「敢」就突然出现了。这不是我变勇敢了。

## 一、忙力所能及的事，是一种安全感

先把话说公道：**只做力所能及的事，不是懦弱，是理性。**

一个人的日常工作可以粗分成两种。一种是「确定性工作」：流程是熟的，工具是熟的，产出是可预期的——写周报、跑例会、改一个明确定义的 bug、维护一条已经稳定运行的流水线。这种工作给人安全感，因为它几乎没有下行风险：做了就有产出，产出就被看见。

另一种是「不确定性工作」：没人做过，方案是赌的，结果可能是零甚至是负的——重构一个「能用但慢」的系统、尝试一种新的协作方式、把一个没验证过的想法做成原型。这种工作的特征是：**下行风险由你承担，上行收益却未必归你。**

理性的成年人会自然滑向第一种。这不是舒适区理论说的那种心理惰性，是一道很简单的算术题：确定性的事，付出就有回报；不确定的事，付出可能打水漂，而且水漂是你自己扔的。

所以「敢于做不确定性的事情是一种稀缺能力」这句话，前半段是废话，后半段才是问题：**它为什么稀缺？**

流行的答案有两个，我觉得都不对。

第一个答案是性格论：有人天生爱冒险，有人天生求稳，所以敢的人少。这个解释的问题是它没法行动——你没法给一个成年人换性格，所有基于性格论的建议最后都只能落成「你要更勇敢一点」，等于没说。

第二个答案是鸡汤论，也就是各种「跳出舒适区」的布道。它比性格论更没用，因为它把稀缺当成了缺陷：好像只要你想，你就能敢。

真正的答案是第三个：**敢，从来都是被成本定价的。**

## 二、勇气是一张价签

把「做一次不确定的尝试」拆开，成本有四行：

```text
一次试错的总成本 = 执行成本 + 判断成本 + 担责成本 + 机会成本

执行成本：把这件事做出来要花的时间和技术能力
判断成本：做错方向的概率 × 做错之后发现的延迟
担责成本：失败之后，谁承担后果、承担多少
机会成本：这些时间本可以去做确定性的事
# generated by hugo AI
```

性格论只盯着第一行里的「技术能力」，鸡汤论四行都不看。而现实里让人却步的，往往不是第一行。

一个工程师不敢重构那个「能用但慢」的系统，很少是因为他不会——是因为搞坏了算谁的（担责），是因为三天工时没人补（机会），是因为「万一方案错了白干一周」（判断）。四行加起来太贵，于是理性的选择就是让它继续慢着。

这套定价逻辑，管理学里早有人研究过。两个坐标：

**Jeff Bezos 在 2016 年股东信里把决策分成两类**：Type 1 是单向门，走过去就回不来，必须审慎；Type 2 是双向门，不满意可以退回来，应该快走快试。他同时指出大公司的通病——**用管理单向门的重流程去管所有的双向门**，结果是缓慢、「未经思考的风险厌恶」（unthoughtful risk aversion）和实验不足。

**Sarasvathy 在 2001 年的 effectuation 研究里发现了专家创业者的反直觉行为**：他们不算上行收益（「这事成了能赚多少」），而是先设定 affordable loss——最多输多少，输得起就做。她研究的那些连续创业者，并不是更爱冒险，恰恰相反，**他们比常人更严格地控制每次下注的最大损失**。

把两个坐标合起来看，结论就出来了：所谓「敢于做不确定的事」的稀缺能力，操作层面从来不是胆量，是 **把一次尝试设计成双向门、设计进 affordable loss 之内的能力**。胆量是性格，设计是技能。性格没法换，技能可以学。

而过去这个技能没什么用武之地——因为四行成本里最贵的执行成本，降不下来。

## 三、AI 撕掉的是第一行价签

回到我那个搜索系统。

拖半年和二十分钟验收的区别，就是执行成本这一行被撕掉了。以前「试一次」的意思是：我自己花三天，期间别的确定性工作全部停摆（机会成本跟着涨）。现在「试一次」的意思是：发一句话，继续开我的会，三个小时后回来看结果——**最坏的情况不是搞坏了线上搜索，而是这个 PR 我不要了。**

注意最坏情况的变化，这才是关键。以前最坏情况是「线上被搞坏 + 三天白干」，现在最坏情况是「点一下 Close」。同一次尝试，下行风险差了两个数量级。按 Bezos 的分类，这件事从一个看起来像单向门的工程（改线上系统），变成了一个彻底的双向门（不满意就不 merge，merge 了还能 revert）。

这不是孤例，是整个行业过去两年发生的事：

- Anthropic 今年 1 月发布 Cowork——把 Claude Code 的 agentic 能力开放给非技术用户——内部团队用大约一周半建成，而且大部分是用 Claude Code 自己写的。一个「先建一个还不灵的东西」的教科书示范：research preview、仅限 Max 订阅用户、边观察边放开。
- Cat Wu（Anthropic Claude Code 产品负责人）8 月底的分享里说，Anthropic 把发布节奏从按季度压到按天，她的座右铭是 Just Do Things，「未来所有岗位都是虚构的，你的价值取决于你实际填补了什么缺口」。
- 我在 [AI 干完了 8 成的活，我才发现需求提错了](https://hugozhu.site/post/2026/397-one-sentence-spec-one-pull-request/) 里写过 PR 这个交付界面的妙处：它天生带着 diff、评论和一票否决权——**否决权就是双向门的门轴**。Agent 交付的东西再完整，merge 之前它对你的世界的影响是零。

所以「AI 让越来越多的人第一次拥有了挑战不确定性的底气」这句话，机制上说得更准一点：**AI 没有给人打气，它把执行成本这一行价签撕掉了。** 底气不是心理建设出来的，是算出来的——当最坏情况从「三天白干加搞坏线上」变成「丢弃一个 PR」，不需要勇气你也敢。

这就是为什么我说这是第一次。以前「敢试」属于两种人：手里有冗余资源的（创业公司的老板、有 20% 时间的工程师），和输得起的（反正没工作的应届生）。执行成本塌下来之后，「敢试」第一次变成普通打工人的可选项——不需要你有资源冗余，只需要最坏情况足够便宜。

## 四、但有三行价签，AI 一行都没撕

写到这里，这篇文章本来可以收在「所以快去试」——那样它就和所有 AI 鸡汤没区别了。

诚实的版本是：四行成本里，AI 只撕掉了第一行。**判断成本、担责成本、机会成本，一分没降，前两样甚至变贵了。**

判断成本变贵，是我用那个搜索 PR 亲自验证过的。Bot 的测试清单五条，条条通过——查询延迟从几十、几百毫秒降到几毫秒，量级上的胜利。但我晚上在家里那条不太行的 Wi-Fi 上按 ⌘K，还是白屏等几秒。它优化的指标（query latency）和我在乎的体感（按下 ⌘K 到看见第一行结果）在这次重构里第一次分了家。**它没错，它只是不知道我要什么——而「知道要什么」这个成本，AI 一点都没替我分担。** 执行越快，判断错误的代价越先到达：以前做错方向，三天执行期就是你发现错误的缓冲期；现在三小时就交付了，错误直接怼到你脸上。

这就是 [AI 重构行业的速度，是可以算出来的](https://hugozhu.site/post/2026/346-ai-disruption-speed-formula/) 那个公式在个人层面的镜像：**模型迭代越快，你的判断越值钱，因为判断是剩下唯一没被加速的环节。**

担责成本没降，反而是组织里最硬的墙。AI 帮你三天做出一个原型，不代表组织允许你拿这个原型去试——审批还在、问责还在、「谁批准上线的」还在。Cat Wu 自己也承认「不是每个人都有 Anthropic 这样的工作环境」。在按天迭代的创业公司，担责成本被文化压到很低；在万人组织里，它纹丝不动。

机会成本也没降，只是换了形态：以前是「三天工时」，现在是「验收和纠偏的时间」。我那个 +98 行的补丁——补进度反馈、补错误态、修两个作用域 bug——就是机会成本的新形态。

所以完整的图景是：

| 成本 | AI 之前 | AI 之后 | 谁承担 |
|---|---|---|---|
| 执行 | 最贵（天级工时 + 技术门槛） | **≈ 一次 merge 点击** | 没了 |
| 判断 | 贵，但被执行周期缓冲 | **更贵，且立刻兑现** | 你 |
| 担责 | 贵 | 没变，组织说了算 | 组织文化 |
| 机会 | 工时 | 验收与纠偏 | 你 |

**执行成本塌方之后，「敢」的稀缺性没有消失，它从第一行迁移到了第二、三行。** 敢做的人确实会变多——因为便宜了；但敢做 **且做得对** 的人，稀缺性反而上升——因为判断成本变贵了。

## 五、和三个月前的自己和解

今年 6 月我写过 [AI 时代，成为有目标感、有判断力、有勇气的人](https://hugozhu.site/post/2026/271-confidence-purpose-judgment-courage/)，里面有一节就叫「勇气：敢在不知道答案时动手」。那篇文章把勇气当成一种品质来呼吁，还在「诚实的注脚」里自我提醒：对编程一无所知的人敢写代码不叫勇气，叫鲁莽。

现在我可以把那篇文章没讲透的部分补上了。当时的注脚其实已经摸到了门：**勇气和执行能力之间的配比，决定了它叫勇气还是叫鲁莽。** 而这个配比之所以在 AI 时代变了，不是因为人的勇气变多了，是因为执行的价签被撕了——鲁莽的下行风险变便宜了，于是很多原来算鲁莽的事，现在重新归类为「值得试的双向门」。

换句话说：那篇讲的是品质（你应该成为一个敢的人），这篇讲的是定价（敢为什么一直稀缺，以及稀缺性迁移到了哪里）。品质论的回答是「锻炼心态」，定价论的回答是「改成本结构」——后者可操作得多。

## 六、「敢」的操作定义：三个问题

把前面全部收拢，「敢于做不确定性的事情」的操作定义不是心态，是三个可以写在纸上的问题。我把那个搜索系统的决策过程代进去验证一遍：

**问题一：错了会输掉什么？这个数字你写得出来吗？**

写不出数字的「敢」是赌，写得出来的才是试错。Sarasvathy 的 affordable loss 就一条要求：下注前先定最大损失。我那次的回答：一个不要的 PR，零线上影响。写得出，且输得起 → 过。

**问题二：错了之后，多久能退回来？谁来退？**

双向门检验。我的回答：merge 前 Close 即可；merge 后 revert 一个 commit，CI 自动回滚，十分钟内线上恢复。退回路径存在且自动化 → 过。**注意这一问的主体经常不是个人而是组织**——如果你的环境里「退回来」需要层层审批，那不是勇气问题，是基础设施问题。这也是我在 [Grok Bot 能当队友，还当不了员工](https://hugozhu.site/post/2026/387-grok-bot-teammate-not-employee/) 里把「可回滚」列为能力治理要素的原因：回滚机制决定了一个 Agent 的产出敢不敢被放进真实流程。

**问题三：这次尝试无论成败，会留下什么？**

试错和浪费的分界线。我那次的回答：就算 PR 不要，我也知道了这个 Bot 在这种任务上的真实边界——这正是 Cat Wu 说的「撞边界」：不亲手做，永远不知道模型在你具体场景下的弱点在哪。留下的东西是资产 → 过。

三问全过才动手，任何一问答不上来就先回去补——补成本结构，不是补勇气。这个检验有个好处：它把「我敢不敢」这种性格问题，翻译成了「这件事设计得够不够便宜」这种工程问题。**性格没法迭代，设计可以。**

写个可执行版本，替你把三问过一遍：

```python
from dataclasses import dataclass


@dataclass
class Trial:
    """一次「不确定的尝试」的成本结构。"""

    name: str
    worst_case_loss: str        # 问题一：最坏输掉什么
    loss_acceptable: bool       # 这个损失在 affordable loss 之内吗
    rollback_path: str          # 问题二：怎么退回来
    rollback_minutes: int       # 退回来要多少分钟
    residue: str                # 问题三：无论成败留下什么


def verdict(trial: Trial) -> str:
    """三问检验：全过才是「值得试的双向门」，否则是赌。"""
    problems = []
    if not trial.loss_acceptable:
        problems.append("最坏损失超出可承受范围——先缩小范围再试")
    if not trial.rollback_path:
        problems.append("没有回退路径——这是单向门，按 Type 1 审慎决策")
    if trial.rollback_minutes > 60:
        problems.append("回退要一小时以上——先建回退机制，再谈勇气")
    if not trial.residue:
        problems.append("失败后什么都不留——这是浪费，不是试错")
    if problems:
        return "别动手，先改设计：\n  - " + "\n  - ".join(problems)
    return "这是双向门：去试"


print(verdict(Trial(
    name="让 Bot 重写博客搜索",
    worst_case_loss="一个不要的 PR，线上零影响",
    loss_acceptable=True,
    rollback_path="merge 前 Close；merge 后 revert + CI 自动部署",
    rollback_minutes=10,
    residue="摸清这个 Bot 在存量系统重构上的真实边界",
)))

print()

print(verdict(Trial(
    name="让 Agent 直接改生产数据库的 schema",
    worst_case_loss="数据损坏，客户可见",
    loss_acceptable=False,
    rollback_path="",
    rollback_minutes=0,
    residue="",
)))
# generated by hugo AI
```

跑出来的结果：

```text
这是双向门：去试

别动手，先改设计：
  - 最坏损失超出可承受范围——先缩小范围再试
  - 没有回退路径——这是单向门，按 Type 1 审慎决策
  - 失败后什么都不留——这是浪费，不是试错
# generated by hugo AI
```

同一句「你敢不敢让 AI 干这个」，两个案例给出完全相反的答案——**差别不在胆量，在成本结构**。这就是定价视角和性格视角的全部分别。

## 七、组织视角：数双向门，别数勇敢的人

最后把镜头从个人拉到组织，因为这篇的成本分析对组织同样成立，而且更扎心。

一个组织「敢于做不确定的事」的能力，取决于的不是里面有多少胆子大的人，而是 **双向门的密度**：有多少件事，员工不用审批就能试、试坏了十分钟能退回来、失败了复盘完不追责。Bezos 说的大公司病，本质就是双向门密度衰减——每加一层审批，就把一批双向门焊成了单向门。

这对 AI 时代的管理是一个具体的动作清单：

- 执行成本已经塌了，别再优化执行效率，**去优化回退机制**——revert、灰度、沙箱、staging，这些决定你的组织里双向门有多少扇；
- 判断成本变贵了，**把「怎样算做对」前置成标准**，别让员工的判断力裸奔——这就是我在 [评测集是一份没人签字的文件](https://hugozhu.site/post/2026/384-eval-set-needs-a-signature/) 里论证的事：验收标准没人签字，执行再快也只是把错误交付得更快；
- 担责成本是组织自己定的，**对「三问全过的失败」免责**——它不是事故，是你花钱买到的边界信息。

## 写在最后

回到开头那三句话：

> 忙力所能及的事情，是一种安全感。
> 敢于做不确定性的事情，是一种稀缺能力。
> 而 AI，让越来越多的人第一次拥有了挑战不确定性的底气。

现在可以给第三句补一个精确的机制：AI 给的不是底气，是 **便宜的试错**。底气这个词听起来像心理状态，便宜的试错是工程状态——后者人人可建，前者只能羡慕。

而稀缺能力的定义也跟着更新了：不再是「敢动手」（动手已经不值钱了），而是 **敢在动手前，把最坏情况算清楚、把退路修好、把成败都变成资产**。这个能力 AI 替不了你，因为三问里每一问的主语都是「你输得起什么」——这是判断，不是执行。

执行的时代结束了，判断的时代刚开始。价签撕掉之后，剩下的都归你。
