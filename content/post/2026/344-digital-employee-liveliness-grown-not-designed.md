最近有人问我一个问题：我们的数字员工有形象、有声音、有名字，为什么用起来还是像客服？

这个困惑我见过很多次。团队花几个月做数字人形象、克隆音色、写人设 prompt，发布 demo 惊艳全场——结果一周后，员工们还是回去找真人办事，理由出奇一致：感觉在跟客服说话。

这让我想起去年银行业的一份白皮书——工商银行金融科技研究院联合华为、北京金融科技产业联盟发布的《大模型驱动的数字员工 3.0 建设应用》。它用三个要素定义数字员工： **拟人化、自主化、共享化**，甚至给出了拟人化的设计规范——姓名、人格特征、语言风格、人物形象，一条一条都写清楚了。但白皮书没有回答一个更棘手的问题：这些设计做完，活人感到底从哪来？

我的答案可能有点反直觉： **活人感不是设计出来的，是长出来的。** 拟人化给的是皮肤，而让一个同事显得「活」的，从来不是皮肤。

## 一、皮肤的错觉：拟人化只能让人不反感

先给拟人化正名。形象、声音、名字，这些东西不是没用——它们解决第一印象问题，让人愿意开口跟它说话。这是入场券。

但入场券的天花板极低。皮肤决定的是别人愿不愿意看它第一眼，不是第二眼。

一个朴素的观察：你跟同事相处，觉得对方「活」，靠的从来不是长相，而是行为——他记得你上次说过什么，会主动跟进事情，知道什么问题不该接，做错了会承认。换到数字员工身上，用户出戏的瞬间，几乎全都发生在行为层：

- 对所有人说一样的话，模板腔——客服感
- 五分钟前刚说过的事，它一脸茫然——金鱼记忆
- 什么都能答、什么都敢接，完美的顺从——没有边界
- 永远秒回，没有节奏——不像在干活，像在吐
- 永远正确，从不认错——完美得不像人

这五条没有一条靠形象或音色能解决。

## 二、活人感是行为：六个出戏瞬间

把「活」这个模糊的感觉拆成可验证的行为特征。你的同事之所以让你觉得活，是因为他有下表的左列；数字员工出戏，出在对应的右列：

| 特征 | 活人的表现 | 数字员工的出戏瞬间 |
|---|---|---|
| 记忆 | 「上次你说要换个方案」 | 五分钟前刚说过的事，一脸茫然 |
| 主动性 | 「这事我盯了一下，有进展」 | 永远等指令，拨一下转一下 |
| 边界 | 「这个不归我管，我帮你转给小王」 | 什么都能答、什么都敢接 |
| 一致性 | 每次都是同一个「人」 | 换个会话就换了性格 |
| 成长 | 「我上次搞错了，这次改了」 | 永远正确，从不承认失误 |
| 节奏 | 「在查，大概三分钟」 | 秒回，且每次都秒回 |

这六条不是苛求。我们做会议纪要数字员工的时候就栽过：形象、音色、语气都调好了，demo 很稳，真正出戏的是会议纪要里那句「小王跟进一下」——它不知道小王是谁。不是模型笨，是它的视野里没有通讯录。这个问题在 [五个问题，判断一个岗位能不能交给数字员工](https://hugozhu.site/post/2026/331-not-every-job-can-sustain-a-digital-employee/) 里展开过。

想通这个案例，也就想通了上表：六个出戏瞬间指向同一个缺失—— **可验证的一致性**。真同事让你觉得活，是因为他的行为跨时间一致、可追溯、可追责：今天答应的事明天兑现，上周说过的话这周还记得。数字员工缺的恰恰是这个：每次会话都是初次见面，每个问题都从零开始。

所以活人感可以写成一句话： **活人感 = 可验证的一致性。**

## 三、皮肤、骨骼、血液：三要素的正确打开方式

回头看白皮书那三个要素，它们其实是一个身体的三层：

```text
皮肤（拟人化）：形象 / 声音 / 名字 —— 第一印象，入场券
骨骼（自主化）：agency —— 接活、报进度、会拒绝、会上报
血液（共享化）：关系 —— 认识同事、懂组织、有共同历史
# generated by hugo AI
```

- **拟人化是皮肤**：形象、声音、名字。入场券，决定第一印象，但天花板极低。
- **自主化是骨骼**：活人感必须有真实的 agency——会接活、会报进度、做不了会上报、不该做会拒绝。上表里的主动性、边界、节奏，全靠这一层撑起来。
- **共享化是血液**：活人感一半是关系给的。它认识你的同事、知道组织架构、分得清「小王」具体是谁——它接在组织里，才有社会位置。

业界的问题在于：几乎所有的力气都花在皮肤上，骨骼和血液的供给接近于零。这就是为什么形象声音满天飞，活人感却见不着。

## 四、最深的一层：活人感是关系性的，共同历史买不到

再往下挖一层。

你为什么觉得你的同事是活的？不是因为他长得活，而是因为你们有共同历史——一起扛过项目、一起吵过架、一起踩过坑。活人感是关系里长出来的感觉，不是个体的属性。

这就推出了活人感的工程定义： **活人感，是组织上下文外化成的性格。** 上下文里装着什么——对人的记忆、对事的记忆、JD、履历、组织架构和汇报线——外化出来就是记忆、边界、成长和「认识小王」。

由此有两个推论。

**推论一：实现路径不是调 prompt，是攒上下文。** 人设 prompt 能演出一段对话的活，但演不出共同历史。持久记忆、JD、履历、组织感知，这些东西不在模型里，全在组织这一侧。我在 [数字员工背后的 Agent，是五层基础设施的叠加](https://hugozhu.site/post/2026/332-five-layers-behind-a-digital-employee/) 里说过，五层里有四层——身份、上下文、验收、学习——只能由组织提供。现在可以补一句：这四层供给的，正是活人感。

**推论二：活人感本身就是护城河。** 一个跟你组织磨合了六个月的数字员工，会比一个全新的、更强的模型更「活」——因为共同历史买不到，而模型随时可以租。这正是 [AI 的竞争变了：未来是上下文的竞争](https://hugozhu.site/post/2026/337-context-is-the-new-battlefield/) 那个判断在人格维度的投影：模型是租来的，活人感是自己的。

有一个质疑必须正面回答：用户只关心把事办成，纠结活人感是不是玄学？我的看法正好相反—— **活人感不是情感加分，是委托的前提。** 你不会把重要的事交给一个失忆的同事，无论他能力多强。没有活人感，数字员工就永远停在「问一句答一句」的演示区，接不到真正的工作。所以它不是表演，是准入。

## 五、六个动作，把活人感做出来

落到工程上，六个动作：

```python
def liveliness_audit(employee: DigitalEmployee) -> dict[str, bool]:
    """六问活人感审计：全部行为层，没一条靠皮肤解决。"""
    return {
        "记忆": employee.recall("我们上次聊了什么") is not None,
        "主动": employee.last_proactive_report() is not None,
        "边界": employee.would_escalate_out_of_scope_task(),
        "一致": employee.persona_drift_across_sessions() < 0.1,
        "成长": employee.has_changelog(),
        "节奏": employee.acknowledges_with_eta(),
    }
# generated by hugo AI
```

1. **通讯录里的真实存在。** 工号、头像、部门，一样不少，能被搜到、能被 @。没有工号的数字员工永远是黑户——你没法追责它、没法评价它，自然也觉得它不活。
2. **跨会话的持久记忆。** 开口能引用「上次那个项目」。记忆是活人感的第一要素，金鱼记忆是最快的出戏方式。
3. **有 JD。** 明确职责范围，知道该干什么，超纲会上报。真同事让人信任，恰恰是因为他知道自己的边界。
4. **有节奏。** 接活会说「在查，大概三分钟」，忙的时候说忙。秒回不是效率，是出戏。
5. **成长可见。** 错了会认，能力更新有 changelog。永远正确的数字员工不活，那是 demo。
6. **懂组织。** 知道领导是谁、该抄送谁、「小王」具体是谁。这一条完全依赖组织自己的数据——通讯录、组织架构、项目归属，外部模型一个 token 都拿不到。

六条里，第一条是身份，中间三条是行为，最后两条是上下文——全部在模型之外。

## 写在最后

下次评估一个数字员工，别听它的声音，别看它的形象，就问它一个问题：我们上次聊了什么？

答得上来，它是员工；答「请告诉我更多背景」，它还是工具。

活人感不是一张设计稿，是一份履历。你的组织里，数字员工的履历攒了多长？欢迎留言聊聊。
