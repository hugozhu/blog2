发完 [从 Cowork 到 Tag：AI 的竞争单位，正在从个人变成组织](https://hugozhu.site/post/2026/353-cowork-tag-unit-shift-person-team-org/) 第二天，那个年轻人又发来一条消息。这次他没提问，而是直接甩了一个判断：

**「对 AI 创业者来说：Anthropic 领先行业 6 个月。」**

他还给了自己的三层拆解：

| 层次 | Anthropic 的领先点 | 领先幅度 |
| --- | --- | --- |
| Foundation Model | Claude 系列整体非常强 | 0-6 个月，且会快速收敛 |
| Agent Harness | Claude Code / Cowork / Tag 形成完整 Agent 工作范式 | ~6 个月 |
| Agent-native Organization | 从「人使用 AI」走向「Agent 成为组织成员」 | ~6-12 个月 |

他的结论是：模型层的领先会快速收敛，真正值得关注的是后两层。而且第三层，恰好是钉钉「数字员工」可以承接的位置。

前两层，我认同。第三层，我认为 **写反了**。

**在 Agent-native Organization 这一层，Anthropic 不是领先者，是刚入场的人。**

## 一、前两层：这个拆法本身是对的

先肯定这个拆解。把「Anthropic 领先」拆成模型、Harness、组织三层，比笼统地说「领先 6 个月」要诚实得多——因为这三层的领先机制完全不同，收敛速度也完全不同。

第一层，Foundation Model。0-6 个月，且快速收敛，这个判断我完全同意。模型层的领先是靠训练投入和迭代速度撑着的，而这两样东西所有头部厂商都不缺。今天 Claude 能做的，半年后别家的模型大概率也能做。**模型层的领先是有保质期的，而且保质期越来越短。**

第二层，Agent Harness。~6 个月，这个数字是经验估算，我没法精确验证，但我认为方向成立。Claude Code、Cowork、Tag 这一串产品，确实比行业早走了一步。

但这里要注意：Harness 层领先的本质，不是「产品发得早」，而是 Anthropic 兑现了一个别人还没想清楚的范式——

**Agent 不一定需要一个传统意义上的 UI。它可以直接占据一个工作空间，自己读取上下文、执行任务、调用工具、产生结果。**

Claude Code 在终端里第一次证明了这句话；Cowork 把它从代码扩展到一般知识工作；Tag 再把它种进团队的协作空间。三个产品，其实是同一句话的三次兑现。传统 AI 产品的范式是「人 → AI → SaaS」，而这条路线正在变成：

```text
传统范式：  人 ──> AI ──> SaaS

新范式：    人 + Agent ──> Workspace ──> SaaS
# generated by hugo AI
```

这 6 个月领先的真正含义是：Anthropic 比所有人更早摸清了「Agent 怎么干活」。

## 二、第三层，写反了

年轻人的表格里，第三层 Agent-native Organization 写着「领先 6-12 个月」。我认为这一行应该倒过来读：**在这一层，Anthropic 和所有人一样，从零开始。**

证据不在别处，就在 Tag 自己身上。

看 Tag 为了在企业里落地，不得不加进产品设计里的东西：跨频道读取要「授权」、花费上限、管理员准入、四步配置流程、从旧版迁移要管理员 30 天内主动 opt-in。这些词没有一个是 Anthropic 发明的——**授权、预算、管理员、审批，全是企业软件用了二十年的治理词汇**。一个模型厂商做团队 Agent，第一天就得借用组织治理的词表。

借用，本身就是没有积累的证据。

为什么 Anthropic 不能顺着频道数据自己长出这一层？[上一篇文章](https://hugozhu.site/post/2026/353-cowork-tag-unit-shift-person-team-org/) 里我给过一句话的理由，这里展开说透：**上下文可以重建，责任不能。**

频道记录、任务历史、成员分工，这些确实是模型可以吃进去的数据，Tag 的频道学习机制已经在这么做了。但组织上下文里真正硬的那部分不是数据，是 **责任结构**——谁有权看什么、谁能派活给谁、出了问题谁担责。这些东西的载体不是聊天记录，是工号、岗位、审批链、审计日志。

关键区别在这里：**记忆是数据，问责是制度。** 数据可以被模型吃掉、重建、复制；制度不行。你可以授权一个有工号的 Claude 读频道，但你没法「授权」一个没有组织身份的东西——它连被问责的资格都没有。模型层可以复制记忆，复制不了问责。

所以这张三层表的正确读法是：

```text
第三层  Agent-native Organization    无主 · 所有人从零开始
        ──────────────────────────────────────────────
第二层  Agent Harness                Anthropic 领先 ~6 个月
        ──────────────────────────────────────────────
第一层  Foundation Model             0-6 个月 · 快速收敛
# generated by hugo AI
```

**前两层它领先，第三层是它必须进来求合作的领域。**

## 三、追赶心态 vs 卡位心态

同一个「领先 6 个月」，两种读法，导出两种完全不同的行动。

| | 追赶心态 | 卡位心态 |
| --- | --- | --- |
| 怎么读这 6 个月 | 要补上的差距 | 对方边界在哪的信号 |
| 动作 | 复刻 Tag，补 Harness | 把组织原语做成绕不开的接口层 |
| 看 Anthropic | 竞争对手 | 未来的集成对象 |
| 结局 | 永远落后 6 个月 | 它进来时，你手里有牌 |

追赶心态的问题不是不努力，而是方向错了：你在别人领先最实、迭代最快的战场上，用别人的规则追别人。Harness 层的 6 个月是 Anthropic 用工程密度和产品节奏堆出来的，正面追，追到的永远是它 6 个月前的位置。

卡位心态则来自第三层的判断：既然问责结构是 Anthropic 长不出来的，那谁手里有现成的问责基础设施，谁就是它绕不开的合作对象。这正是我在 [AI 钉钉的护城河不在 AI，而在组织图谱与协同飞轮](https://hugozhu.site/post/2026/297-dingtalk-moat-org-graph-collaboration-flywheel/) 里论证过的那套东西——组织图谱、审批链、审计日志、汇报线。只是那篇讲的是防守：别人搬不走。这篇要补上它的进攻面：

**护城河不只是防 Anthropic 进来的防线，更是它进来谈判时，你手里的牌。**

## 四、那 AI 创业者该怎么办

如果这篇的读者是 AI 创业者，这一节是我最想说的。

第一件事，**不要在通用 Harness 层和 Anthropic 正面打**。那是资金、分发、迭代速度三重碾压的战场。Claude Code 的迭代速度、Anthropic 的开发者心智、加上模型和 Harness 的同源优化——通用编程 Agent、通用办公 Agent 这类位置，窗口基本已经关上了。这和 [AI 机会在变少：2026-2027 是最后的关键期](https://hugozhu.site/post/2026/194-ai-opportunity-closing-window-2026-2027/) 里说的是同一件事：通用层的收敛比所有人预期的都快。

第二件事，**窗口在垂直行业的组织层**。Anthropic 做横向平台，永远做不深的东西，恰好是每个行业最值钱的东西：行业 SOP、合规要求、审计标准、责任链。一个医疗行业的 Agent 怎么留审计痕迹、一个金融机构的 Agent 谁有权派活、一个制造企业的质检 Agent 出了错责任怎么划分——这些不是 prompt 问题，是行业制度问题。而制度知识，是横向平台不愿意做、创业公司做了别人拿不走的东西。

把第二节的两层判断合起来，创业者的位置其实很清楚：

```text
通用 Harness 层：  别去 —— Anthropic 的主场
垂直行业组织层：   去   —— 制度知识是纵深，平台做不深
# generated by hugo AI
```

一句话：别追那 6 个月，去找那 6 个月照不到的地方。

## 五、别把路线图当地图

最后还有一处要修正。年轻人顺手画了一条时间线：2025 年 AI = Copilot，2026 年 AI = Agent，2027 年 AI = Worker，2028 年 AI = Organization——人加 Agent 共同组成组织。

这条线作为路标是好的，它的大方向我同意。但 **别把它当地图**。

真实的采用从来不是按年份切换范式的，而是按 **信任梯度** 推进的。同一家公司里，三个范式会长期并存：工程团队可能已经在用 Worker 级的 Agent 提交代码，财务部门还停在 Copilot 阶段，法务可能连 Copilot 都还没敢上。决定一个团队处在哪个阶段的，不是日历，是这个团队愿意把多大的责任交给 AI——而信任的建立速度，每个行业、每个职能、每个组织都不一样。

这条修正的实践含义是：**不要赌「范式哪一年切换」，要赌「范式到来时，位置在谁手里」。** 前者你赌不中，后者你可以现在就动手。

## 六、所以，把判断升级一下

回到开头那个判断。「Anthropic 领先行业 6 个月」这句话本身没错，但它省略了最关键的部分——领先的是哪一层，以及每一层该怎么应对。升级后的版本是：

> **Anthropic 领先行业的，是 6 个月的「AI 如何干活」的产品探索；而「AI 如何在组织里被问责」这一层，它必须来找我们。**

如果要用一句话收尾，我会把年轻人原文里那句「Anthropic 定义 Agent 怎么工作，钉钉定义 Agent 在组织里怎么工作」改成：

> **Anthropic 定义「Agent 怎么工作」，组织平台定义「Agent 在组织里怎么工作」——前者领先 6 个月，后者是它必须来找我们的理由。**

模型层的领先会过期，Harness 层的领先会被追平，只有位置不会。**你现在卡在哪一层？** 欢迎留言聊聊。
